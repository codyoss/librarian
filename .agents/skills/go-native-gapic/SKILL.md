# Native Go GAPIC generation

Moving Go GAPIC generation out of the external `protoc-gen-go_gapic` plugin and
into Librarian as a native sidekick codec, the same way Rust, Dart and Swift
work.

Read [sidekick-add-language](../sidekick-add-language/SKILL.md) first for the
codec mechanics. This skill covers what is specific to Go.

## Scope

**In scope:** the GAPIC surface. Clients, iterators, examples, `doc.go`,
metadata, LRO wrappers.

**Out of scope:** `*.pb.go` message and gRPC stubs. Those keep coming from
protoc. Do not touch them.

## The correctness bar

Byte-for-byte equality with what is already checked into `google-cloud-go`.
Not "compiles", not "looks right". Identical bytes.

This is the whole reason the project is tractable: correctness is not a
judgement call, and progress is a number.

Gate 1 is **43 files** across two targets:

| Target | Client dir | Notes |
|---|---|---|
| `run` | `run/apiv2` | 8 services, LRO, IAM + Locations mixins, gRPC **and** REST |
| `secretmanager` | `secretmanager/apiv1` | 1 service, gRPC + REST, native IAM RPCs |

## The harness

Everything is measured, never assumed. Scripts live in `<workspace>/harness/`.

```bash
./harness/diff.sh run secretmanager   # the oracle: regenerate and diff
./harness/run-librarian.sh generate run  # safe wrapper with GOMEMLIMIT and timeout
./harness/scoreboard.sh               # per-file progress table
./harness/focus.sh run services_client.go   # one file at a time
./harness/assert-formatted.sh         # output must be a goimports fixed point
./harness/test.sh                     # unit tests with protoc on PATH
./harness/worktree.sh <name>          # isolated oracle for a parallel worker
```

Read `harness/README.md` before using them. It documents the traps each script
exists to prevent.

**Never call `harness/bin/librarian` directly.** Always invoke it via
`./harness/run-librarian.sh` or `./harness/diff.sh`. These enforce
`GOMEMLIMIT=4GiB` and a 120-second timeout to prevent runaway memory consumption
and OOM crashes.

## Concurrency: read this before running anything in parallel

**The oracle is a single shared mutable resource.** `diff.sh` writes into the
`google-cloud-go` tree and then reads `git diff`. Two agents running it at once
interleave their writes and produce phantom diffs that do not reproduce, which
is a spectacularly expensive way to waste time.

Rules:

1. One worker, one `git worktree`. Create it with `harness/worktree.sh <name>`
   and point the harness at it with `GCG_OVERRIDE=<path>`. Always invoke
   generation via `./harness/run-librarian.sh` or `./harness/diff.sh`.
2. Never clone `google-cloud-go`. It is 1.1 GB. Worktrees share the object
   store.
3. Never leave the tree dirty. Every harness script refuses to run against a
   dirty tree, which protects you, but a crashed worker still needs cleanup:
   `git -C <repo> checkout -- . && git -C <repo> clean -fd`.
4. Prefer hermetic unit tests as the inner loop. Only touch the real oracle when
   you need to confirm.
5. Strictly adhere to Gate 1 scope (`run`, `secretmanager`). Do not attempt to
   generate out-of-scope libraries (such as `spanner`) until Gate 1 is green.

## Settled design decisions

Do not relitigate these.

1. New package `internal/sidekick/golang`, signature
   `Generate(ctx, model, outdir, cfg *parser.ModelConfig)`, matching Rust.
2. **Zero shared-IR changes. Zero interface changes.** Everything Go-specific
   goes in the `Codec` annotation fields.
3. Templates emit `// Code generated by protoc-gen-go_gapic. DO NOT EDIT.`
   verbatim. The marker means "this file is generated" and belongs in the
   template.
4. Copyright year comes from config, never from the clock.
5. Keep the existing `Format` phase, but assert it is a no-op. The checked-in
   bytes are already a `goimports` fixed point, so the codec must emit final
   bytes directly.
6. Mixins are handled codec-side. Never mutate `service.Methods`.
7. Sort keys before any output-bearing map iteration.

## Known divergences from the stock generator

These are measured, not theorised. Each one will produce a diff if ignored.

### Mixin method ordering

`gapic-generator-go` emits mixin methods in service-config `http.rules` order.
Librarian's parser yields proto declaration order. These differ on both golden
targets.

Empirically, across 176 mixin group instances in 99 shipped client files, the
order is **100% alphabetical within a group**, and groups always appear in the
order Locations, IAMPolicy, Operations. Sorting codec-side reproduces the
shipped output. Do this rather than changing any interface.

### The mixin gate is `http.rules`, not `apis:`

`run_v2.yaml` lists Locations under `apis:` but declares no Locations
`http.rules`, and the shipped clients correctly have no Locations mixin. Gating
on `apis:` would wrongly emit `GetLocation`/`ListLocations` on all 8 `run`
clients.

### Two suspected divergences that do NOT fire

Both were measured and refuted on the golden targets. Do not spend time on them
unless a scoreboard row actually goes red:

- Forced `GetOperation` injection when a method returns an LRO.
- IAM mixin suppression when a service natively redefines an IAM RPC.

### `run/apiv2` has REST

An early investigation concluded it was gRPC-only. That was wrong: `grep` for
`restClient` is case-sensitive and misses `servicesRESTClient`. REST is in Gate
1 scope, and `genrest.go` (1,299 lines) is the largest reference file.

## Files you must not touch

The scoreboard flags these as `VIOL` rather than progress:

- `run/apiv2/locations_client.go` - frozen via `keep:` in `librarian.yaml`.
- `secretmanager/apiv1/iam.go` and `iam_example_test.go` - hand-written since
  2020. They survive `Clean` only because they match no generated pattern.

Note that `internal/librarian/golang/clean.go` lists the files the generator
*deletes*, which is not the same as the files it *writes*. `version.go` is
written but not listed there.
